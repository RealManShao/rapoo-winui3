# Rapoo VT1 Air Max 控制协议

本文记录 Rapoo VT1 Air Max 2.4 GHz 接收器的 DPI、档位开关、回报率和电量协议，以及 Rapoo Control 的实现边界。报文与顺序依据仓库内的 [USBPcap 抓包](../wireshark/) 整理；保留未知字段，不为未知语义命名。

## 设备与传输

| 项目 | 值 |
| --- | --- |
| USB Vendor ID | `0x24AE` |
| USB Product ID | `0x1234` |
| 抓包中的配置接口 | USB Interface `1` |
| 配置输出报告 ID | `0xBA` |
| 配置报告长度 | 32 字节，未使用的尾部字节填 `00` |
| 配置写入 | HID `SET_REPORT`，`wValue=0x02BA`（Output Report） |
| 配置应答读取 | HID `GET_REPORT`，`wValue=0x01BA`（Input Report） |
| 电量输入报告 ID | `0xBB` |
| 抓包中的电量输入端点 | `0x84` |

C# 使用 `HidD_SetOutputReport` 写入配置，使用 `HidD_GetInputReport` 读取配置应答；电量通过异步读取 HID 输入报告接收。设备枚举同时校验 VID / PID、collection caps 和 BA / BB Report ID；检测到多个配置接口时拒绝广播写入。对常规鼠标 collection 不申请读写权限，不读取鼠标移动数据。

以下字节偏移均从 `0` 开始；输出报文偏移包含报告 ID，应答偏移按各节说明计算。多字节 DPI 数值使用小端序。

DPI/回报率等原有配置写入事务中，每条 Output Report 发送后，以约 50 ms 间隔查询两次 Input BA，与对应抓包节奏一致。新抓到的传感器参数事务每条 Output Report 只查询一次 Input BA。应答原文进入通信日志，其语义不用于断言设备持久化成功。显式读取当前配置则使用后文所述的最多五次读取策略。读取与写入使用同一个事务锁，避免控制传输交错。

## DPI 与档位开关

支持 7 个 DPI 档位，每档可独立启用或关闭，至少启用一档。DPI 范围为 **50–45000**，步进为 **50**。

### 配置报文

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0–3 | 4 | 固定值 `BA A5 A5 10` |
| 4–7 | 4 | 第一条为 `88 08 00 00`，第二条为 `C8 08 00 00` |
| 8–21 | 14 | 7 个 16 位无符号 DPI 值，小端序 |
| 22 | 1 | 启用档位数减一，范围 `00`–`06` |
| 23–31 | 9 | `00` |

DPI 值按以下规则排列：

1. 启用档位在前，按界面档位顺序排列。
2. 关闭档位在后，同样按界面档位顺序排列。
3. 全部启用时，依次为档位 1–7。

例如，启用 4 档时，偏移 22 为 `03`；启用全部 7 档时为 `06`。1450 DPI 编码为 `AA 05`。

### 写入顺序

依次发送以下 5 条 32 字节 Output Report；省略部分以 `00` 补齐：

```text
BA A5 A4 18 98 08 00 00 ...
BA A5 A5 10 88 08 00 00 <14 字节 DPI 列表> <启用数减一> ...
BA A5 A5 10 C8 08 00 00 <14 字节 DPI 列表> <启用数减一> ...
BA A5 A4 18 98 08 00 00 ...
BA A5 A3 00 00 00 00 00 ...
```

联动模式下两条 DPI 配置报文的 DPI 列表一致，独立 X/Y 时分别包含两个方向的列表；启用数量始终一致。联动写入来源：`enable7dpi.pcapng` 第 297、303、309、343、365 帧，独立 X/Y 证据见文末适配核对。

### 编码示例

七档分别为 800、1450、400、1200、3200、6400、45000 DPI，且全部启用时，第一条 DPI 配置报文为：

```text
BA A5 A5 10 88 08 00 00 20 03 AA 05 90 01 B0 04 80 0C 00 19 C8 AF 06 00 00 00 00 00 00 00 00 00
```

第二条仅将偏移 4 的 `88` 改为 `C8`。

## 回报率与配置读取

### 回报率代码

支持 **125 / 250 / 500 / 1000 / 2000 / 4000 / 8000 Hz**。

| 回报率 | 单字节协议代码 |
| ---: | --- |
| 125 Hz | `08` |
| 250 Hz | `04` |
| 500 Hz | `02` |
| 1000 Hz | `01` |
| 2000 Hz | `84` |
| 4000 Hz | `82` |
| 8000 Hz | `81` |

七档代码均已内置，界面选择后即可应用，无需本地 JSON 扩展；旧版扩展配置不能覆盖内置值。

### 当前回报率读取

应用回报率后，发送以下 32 字节请求，读取 `0x0880` 起始的 4 字节区域：

```text
BA A5 A4 04 80 08 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

发送后等待约 50 ms，以 HID `GET_REPORT` 读取 Input BA；应答未就绪时，在同一次事务中最多尝试 5 次，每次间隔 50 ms。不重复发送读取请求，不启动后台轮询。

抓包应答为 `01 00 00 00 CODE 01 01 FF`，前 4 字节为状态，偏移 4 的 `CODE` 按上表映射。例：`01 00 00 00 82 01 01 FF` 表示设备配置为 4000 Hz。解析兼容 Windows HID 缓冲区的前导 `BA` 报告 ID 及尾部补零，并校验头部及 `00/01 01 FF`（其中 `00` 来自设备日志）；ACK、短报文和未知代码不参与更新。只在明确请求读取 `0x0880` 的上下文解析，避免将其他配置应答误认为回报率。

抓包证据：

- `125hz.pcapng` 第 7 帧为读取请求，第 10 帧返回 `01 00 00 00 01 01 01 FF`，表示写入 125 Hz 前为 1000 Hz；第 28 帧长读取返回的同一字段变为 `08`。
- `250-2000hz.pcapng` 第 433–436、567–570 帧包含读取请求与应答；第 436、570、776、1116 帧依次返回 `08`、`04`、`02`、`01`。
- `1k-4k-8k.pcapng` 第 3975–3978 帧包含读取请求与应答，第 3978 帧在写入 8000 Hz 前返回 `82`，即 4000 Hz。

此处读取的是设备配置值，不用于证明实际输入达到该频率。

### 完整 DPI 与回报率配置读取

连接时和应用 DPI 后，使用长读取 `BA A5 A4 18 80 08 00 00 …`，读取 `0x0880` 起始的 24 字节配置，获得 X DPI 和回报率，再查询 `BA A5 A4 10 C8 08 00 00 …` 读取七档 Y DPI 与启用数量。两次读取在同一事务锁内完成。请求仍为 32 字节，剩余字节填零；等待和重试规则与短读取相同，连续命令间保留约 50 ms。

去掉可选的 `BA` 报告 ID 后，应答布局为：

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0–3 | 4 | 状态，校验为 `01 00 00 00` |
| 4 | 1 | 回报率代码 |
| 5–7 | 3 | 固定值 `01 01 FF` |
| 8–11 | 4 | 保留原始值，未解释 |
| 12–25 | 14 | 七个小端序 DPI |
| 26 | 1 | 启用档位数减一 |
| 27 | 1 | 保留原始值，未解释 |

前 N 档启用，其余关闭。对应证据为 `250-2000hz.pcapng` 第 454 帧。解析校验全部 DPI 的范围、步进和启用数量；失败不采用部分数据。设备按启用档位在前的顺序存储，重新加载后档位编号按设备存储顺序排列，不保留本地旧编号。

### 回报率配置报文

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0–7 | 8 | 固定值 `BA A5 A5 04 80 08 00 00` |
| 8 | 1 | 回报率协议代码 |
| 9–11 | 3 | 固定值 `01 01 FF` |
| 12–31 | 20 | `00` |

依次发送以下 4 条 32 字节 Output Report；省略部分以 `00` 补齐：

```text
BA A5 A4 04 80 08 00 00 ...
BA A5 A5 04 80 08 00 00 <回报率代码> 01 01 FF ...
BA A5 A3 00 00 00 00 00 ...
BA A5 A4 18 80 08 00 00 ...
```

来源：`250-2000hz.pcapng` 第 433–451 帧及其后三组。

`125hz.pcapng` 的整组输出位于第 7、11、19、25 帧，顺序与上述四条事务一致。第 11 帧配置报文为：

```text
125 Hz: BA A5 A5 04 80 08 00 00 08 01 01 FF 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

`1k-4k-8k.pcapng` 中，4000 Hz 的整组输出位于第 1927、1931、1935、2037 帧；8000 Hz 位于第 3975、3995、4001、4005 帧，顺序与上述四条事务一致。其中两条完整配置报文为：

```text
4000 Hz: BA A5 A5 04 80 08 00 00 82 01 01 FF 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
8000 Hz: BA A5 A5 04 80 08 00 00 81 01 01 FF 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

## 电量与当前 DPI

电量输入报告有效数据为 7 字节：

```text
BB B0 71 <DPI 低字节> <DPI 高字节> 01 <电量百分比>
```

| 偏移 | 长度 | 内容 |
| --- | ---: | --- |
| 0–2 | 3 | 固定值 `BB B0 71` |
| 3–4 | 2 | 当前 DPI，16 位无符号整数，小端序 |
| 5 | 1 | 固定值 `01` |
| 6 | 1 | 电量百分比，整数范围 0–100，即 `00`–`64` |

例如，以下报文表示当前 DPI 为 **1450**，电量为 **35%**：

```text
BB B0 71 AA 05 01 23
```

解析检查消息头、固定字段和百分比范围，允许 HID 驱动补齐尾部。应用直接异步读取声明了 BB Input Report 的 HID collection，仅被动等待设备输入，不发送电量查询命令，也不使用电量刷新定时器。

服务只保留最新一条有效电量报告及接收时间；电量或当前 DPI 变化时才通知界面。重复报告仅更新缓存与日志时间，不触发电量界面刷新。断线或重连清空缓存，等待下一条设备报告。待处理的电量界面通知合并为最多一项，避免报告突发时积压 UI 队列。

DPI 菜单高亮所有已启用且数值等于最近 BB 报告当前 DPI 的档位，并标注“当前 DPI”。BB 不含档位编号，多个启用档位具有相同 DPI 时会同时高亮，无法区分唯一档位。未应用的编辑不代表设备配置已改变，没有匹配档位时不猜测当前档位。修改编辑值不向设备发送查询；新报告、断线和编辑只重新计算七个档位的匹配状态。

## 应用行为与实现边界

界面只采用设备读回配置，不加载或保存本地 `settings.json` 中的 DPI／回报率，不提供“恢复默认值”。初始编辑值为空，连接后读取鼠标实际配置；读取失败时保持未读取状态并禁用编辑，重新连接可重试。配置仅在点击应用后写入设备。

连接时和应用 DPI 后各读取完整配置一次，应用回报率后只读取回报率确认。界面的“当前回报率”使用设备读回值，下拉框选择值和发送值不会代替读回结果。读取失败或无法识别应答时显示 `—`；断线后清空当前值。读回失败不使原本可用的配置连接失效。通过其他软件修改配置后，需要重新连接才会更新显示。

Input BA 的主动读应答只用于连接时读取完整配置、用户点击应用设置的配置事务，以及应用后的一次读回确认。后台没有状态轮询或常规鼠标输入采集。

若要测量实际回报率，需要另外采集鼠标移动输入并统计到达间隔；静止、调度和事件合并都会影响测量，结果不等同于设备配置值。高回报率输入的采集与统计会增加主机处理开销，具体影响需要实测，当前未启用此功能。

## 通信日志

通信日志只在内存保留最近 128 条不同内容，按方向及完整报文文本去重。相同内容更新接收时间并移至最后一条；超出上限时淘汰最久未出现的记录。单条诊断文本最多保留 2048 字符。

日志不再写入 `communication.log`，旧日志文件不会继续增长。日志面板收起时不拼接显示文本、不向 UI 排队刷新；展开时才生成文本，连续待处理的日志通知也合并为最多一项。日志用于最近状态诊断，经过合并后无法还原完整事务时序。

## 新增参数、X/Y 与 DIY 按键

对应抓包、实测编码和保留字段见 [一代功能适配核对](GEN1-COMPATIBILITY.md)。应用已实现：

- `0884` 四字节块：LOD（`01/02/03` 对应 0.7/1/2 mm）和移动同步。
- `08C0` 四字节块：按下去抖、抬起去抖、休眠分钟及两种修正的反向位。仅修改低两位，保留高位。
- `08C4` 四字节块：有符号传感器角度、玻璃追踪；其余字节保留。
- X/Y 表分别写 `0888`、`08C8`，排序时保持每档两个方向配对；两个表使用相同启用数量。连接与应用 DPI 后分别读取 X 与 Y，任何一张表格式或启用数无效都不开放 DPI 编辑。
- `0634` 底部 DIY 键：禁用 `07 00 00 00`、中键 `03 00 04 00`、键盘 A `00 00 04 00`、回报率切换 `0A 00 00 00`。通过 `0630` 的 24 字节读取获取该动作。其他动作仅读取并保留，不猜测编码。

参数写入前，在同一事务锁内重新读取三个原始块，保留未知字节，再按照抓包顺序写入并提交。传感器事务每条输出报告间隔约 50 ms 读取一次 Input BA，与 `10-22.pcapng` 一致。应用后读取实际参数并比较全部语义字段；不一致显示实际值并提示，读取失败禁用对应区域。X/Y 编辑开关只控制编辑联动，关闭会将编辑中的 X 复制给 Y，应用时才写入；重连根据两张表是否不同显示编辑方式。

这些查询均为用户连接或应用操作触发，没有新增后台轮询。不同设置区域分别维护读取是否成功，某区域失败不以默认值替代未知状态。
