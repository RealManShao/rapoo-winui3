# 实现中的报文布局

以下索引均从 0 开始。所有配置报文为 32 字节，剩余字节填零。报文顺序来自仓库内的 pcapng；保留未知字段，不为未知语义命名。

## DPI / 档位

| 偏移 | 值 |
| --- | --- |
| 0–3 | `BA A5 A5 10` |
| 4–7 | 第一条 `88 08 00 00`；第二条 `C8 08 00 00` |
| 8–21 | 七个 little-endian ushort DPI，启用档位在前，两组内保持 UI 原顺序 |
| 22 | 启用档位数减一 |
| 23–31 | 零 |

发送顺序：`BA A5 A4 18 98 08 …` → DPI `88` → DPI `C8` → `BA A5 A4 18 98 08 …` → `BA A5 A3 00 …`。来源：`enable7dpi.pcapng` 第 297、303、309、343、365 帧。

例如七档全部启用：

```text
BA A5 A5 10 88 08 00 00 20 03 AA 05 90 01 B0 04 80 0C 00 19 C8 AF 06 00 00 00 00 00 00 00 00 00
```

## 回报率

回报率通过独立的 `BA A5 A4 04 80 08 00 00 …` 读取请求获取：发送后等待约 50 ms，读取 Input BA；未取得数据时最多尝试 5 次，每次间隔 50 ms，仅限本次显式事务，不重复发送请求或启动后台轮询。抓包应答 `01 00 00 00 CODE 01 01 FF` 的偏移 4 为当前回报率代码，代码映射同写入。解析兼容前导 BA 报告 ID 和尾部补零，并校验头部及 `01 01 FF`；ACK、短报文及未知代码不参与更新。仅在明确请求读取 0x0880 的上下文解析，避免误认其他地址的数据。

证据：`125hz.pcapng` 第 7 帧读取请求，第 10 帧返回 `01 00 00 00 01 01 01 FF`（写入 125 Hz 前为 1000 Hz）；第 28 帧长读取返回的同一字段变为 `08`。`250-2000hz.pcapng` 第 436、570、776、1116 帧依次返回 `08`、`04`、`02`、`01`。`1k-4k-8k.pcapng` 第 3978 帧在写入 8000 Hz 前返回 `82`（4000 Hz）。

连接和应用 DPI 后使用长读取 `BA A5 A4 18 80 08 00 00 …` 读出 24 字节配置，复用同一个事务获得 DPI 及回报率。去掉可选 BA 报告 ID 后，偏移 12–25 为七个小端序 DPI，偏移 26 为启用档位数减一，前 N 档启用。对应 `250-2000hz.pcapng` 第 454 帧。校验所有 DPI 范围、步进和启用数量；失败不采用部分数据。设备按启用在前的顺序存储，重新加载后不保留本地旧编号。

界面只采用设备读回配置；不再加载或保存本地 DPI/回报率配置，也没有恢复默认值功能。初始编辑值为空，读取失败时禁用编辑。连接时和应用 DPI 后各读取完整配置一次，应用回报率后只读回报率确认，不持续轮询。失败显示未知，不把发送值或本地配置冒充当前值。读回失败不使原本可用的配置连接失效。读取使用同一个事务锁，避免与配置写入交错。该值是设备配置快照，不是实时输入频率测量；第三方修改后需重新连接才会更新。

若要测量实际回报率，需要另外采集鼠标移动输入并统计到达间隔；静止、调度和事件合并都会影响测量，结果不等同于设备配置值。高回报率输入的采集与统计会增加主机处理开销，具体影响需要实测，当前未启用此功能。

发送顺序：`BA A5 A4 04 80 08 …` → `BA A5 A5 04 80 08 00 00 CODE 01 01 FF …` → `BA A5 A3 00 …` → `BA A5 A4 18 80 08 …`。来源：`250-2000hz.pcapng` 第 433–451 帧及其后三组。

已提供代码：125 Hz → `08`，250 Hz → `04`，500 Hz → `02`，1000 Hz → `01`，2000 Hz → `84`，4000 Hz → `82`，8000 Hz → `81`。七档均已内置，无需本地 JSON 扩展。

`125hz.pcapng` 的整组输出位于第 7、11、19、25 帧，顺序与上述四条事务一致。第 11 帧配置报文为：

```text
125 Hz: BA A5 A5 04 80 08 00 00 08 01 01 FF 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

`1k-4k-8k.pcapng` 中，4000 Hz 的整组输出位于第 1927、1931、1935、2037 帧；8000 Hz 位于第 3975、3995、4001、4005 帧，顺序与上述四条事务一致。其中两条配置报文为：

```text
4000 Hz: BA A5 A5 04 80 08 00 00 82 01 01 FF 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
8000 Hz: BA A5 A5 04 80 08 00 00 81 01 01 FF 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00 00
```

程序内置这两个代码，界面选择后即可应用；旧版扩展配置不能覆盖内置值。

## 传输与电量

每条输出之后间隔约 50 ms 查询两次 Input BA，与抓包中的控制传输节奏对应。应答原文写入日志；其语义不用于断言设备持久化成功。应用不发送臆造的电量查询命令，直接异步读取声明了 BB Input Report 的 HID collection。

电量格式：`BB B0 71 DPI_LO DPI_HI 01 PERCENT`。检查消息头、固定字段和百分比范围，允许 HID 驱动补齐尾部。仅被动异步等待设备输入，不主动查询电量，不使用电量刷新定时器。服务只保留最新一条有效电量报告（含接收时间），电量和当前 DPI 变化时才通知界面；重复报告仅更新缓存与日志时间，不触发电量界面刷新。断线或重连清空缓存，等待下一条设备报告。待处理的电量界面通知合并为最多一项，避免报告突发时积压 UI 队列。

通信日志仅在内存保留最近 128 条不同内容（按方向及完整报文文本去重），相同内容更新接收时间并移至最后一条。新记录超出上限时淘汰最久未出现的记录；单条诊断文本最多保留 2048 字符。日志不再写入 `communication.log`，旧日志文件不会继续增长。日志面板收起时不拼接日志文本、不向 UI 排队刷新；展开时才生成文本，连续的待处理日志通知也合并为最多一项。由于去重，日志用于最近状态诊断，不用于还原完整事务时序。

Input BA 的主动读应答只用于连接时读取完整配置、用户点击应用设置的配置事务，以及应用后的一次读回确认；后台没有状态轮询或常规鼠标输入采集。

DPI 菜单高亮所有已启用且数值等于最近 BB 报告当前 DPI 的档位。BB 不含档位编号，重复 DPI 无法区分唯一档位；编辑区初始来自设备读回值，未应用的编辑不代表设备已改变，未匹配时不猜测档位。修改编辑值不向设备发送查询；新报告、断线和编辑只重新计算七个档位的匹配状态。

设备枚举同时校验 VID / PID、collection caps 和 BA / BB Report ID；多接收器时拒绝广播写入。对常规鼠标 collection 不申请读写权限，不读取鼠标移动数据。

Win32 API 参考：[HID API](https://learn.microsoft.com/windows-hardware/drivers/hid/introduction-to-hid-concepts)。WinUI 非打包部署参考：[Microsoft 文档](https://learn.microsoft.com/windows/apps/package-and-deploy/unpackage-winui-app)。
