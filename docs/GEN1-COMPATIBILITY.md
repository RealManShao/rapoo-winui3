# 一代功能适配核对

核对对象：VT1 Air Max（官方驱动显示 `VT1Air MAX HSDM`），2.4 GHz 接收器。参考源码为仓库根目录的 `protocol_api_rapoo.js`；其中的注释和默认能力是待验证线索，不代表一代设备规范。

## 传输与数据布局

| 项目 | JavaScript 参考实现 | 本仓库已验证的一代协议 |
| --- | --- | --- |
| 写入报告 | Report ID 6，多种长度及 Output/Feature 回退 | Output BA，32 字节 |
| 主动读取 | Feature Report 8 | Input BA，GET_REPORT |
| 被动状态 | Report 7/0，`20` 开头 | Report BB，`BB B0 71` 开头 |
| 写入结束 | 主要是直接写寄存器后更新缓存 | 已有 DPI/回报率事务包含 `BA A5 A3` 提交 |
| DPI | 默认六档、50–26000、步进 10 | 七档、50–45000、步进 50 |
| 档位数量 | 单独写 `0x0896` | 已验证写入 DPI 表的偏移 22 |
| X/Y 表 | `0x0888`/`0x08C8`，可分别设置 | 已抓到独立 X/Y 表；当前应用仍双写相同数据 |
| 回报率 | `0x0880` 单字节写 | `0x0880` 四字节写，保留 `01 01 FF` |

因此不能通过替换 Report ID 就直接移植 JavaScript 驱动。现有传输、应答验证、事务锁及提交顺序应保留。

| Windows 指针/滚轮速度 | 不属于参考设备寄存器配置 | 官方界面提供 Windows 设置；须与设备存储设置分开验证 |

## 参考文件中需避免的行为

- `setButtonMappingBySelect` 用 `if (!addr)` 判断地址，导致合法的左键地址 `0x00` 被拒绝。移植时须检查地址是否存在，而非真假值。
- 多处 DPI 转换和校验仍把上限硬限制为六档；仅修改 profile 不足以支持七档。
- `debounceMs` 会同时写 `C0`、`C1`，无法保持一代按下和抬起设置独立。
- 参考文件把按键 6 的 `0634` 标注为 DPI 键，本机实测是底部 DIY 键。不能照搬物理键地址表。
- 一代禁用动作实测为 `07 00 00 00`，参考文件会将 `funckey=07,keycode=0` 编为 `03 00 07 00`，不适用。
- 成功发送后直接信任本地 `nextState`，不能证明设备已应用或持久化。新增功能应明确读取上下文并读回确认。
- 传输失败后尝试截断报文、切换 Feature/Output 和多种长度，不应移入已有一代的固定报告实现。

## 抓包方法

用户提供的显示过滤器可写为一行（不含 Markdown 转义）：

```wireshark
usb.device_address == 10 && !(_ws.col.info == "URB_INTERRUPT in")
```

地址 10 是本次总线枚举值，重插接收器后须重新确认。该过滤器会隐藏被动 BB 状态；检查电量时需要保留相应中断输入。

只分析控制传输可用：

```wireshark
usb.device_address == 10 && usb.transfer_type == 0x02
```

每个设置记录原值、修改值、恢复值，分别比较读取、写入、ACK、提交和读回。共用寄存器须覆盖开关组合；角度须覆盖正、负、零。鼠标需要物理唤醒，模拟输入不能证明鼠标已醒。

本次新增抓包之前的仓库抓包已用 tshark 扫描：配置输出仅发现 DPI（`0888/08C8`、读 `0898`）、回报率（`0880`）和提交命令，没有其他功能的配置写入证据。

## 2026-10-21 第一轮抓包

文件：`wireshark/gen1-features-20261021.pcap`。仅捕获地址 10，snaplen 256。

输出报告均为 32 字节，以下用四字节数据块展示，尾部补零。长度字段为 `04`，不能把相邻设置覆盖成默认值。

| 操作 | 寄存器块 | 数据 | 代表帧 |
| --- | --- | --- | ---: |
| 移动同步开 | `0884` | `02 01 01 00` | 1701 |
| 移动同步关 | `0884` | `02 00 01 00` | 1735 |
| 直线、波纹都关 | `08C0` | `02 02 05 03` | 1681、1869 |
| 仅直线开 | `08C0` | `02 02 05 02` | 1751 |
| 两项都开 | `08C0` | `02 02 05 00` | 1795 |
| 仅波纹开 | `08C0` | `02 02 05 01` | 1829 |
| LOD 0.7 mm | `0884` | `01 00 01 00` | 1909 |
| LOD 2 mm | `0884` | `03 00 01 00` | 1927 |
| LOD 1 mm（恢复） | `0884` | `02 00 01 00` | 1947 |
| 玻璃追踪开 | `08C4` | `00 01 01 00` | 1967 |

移动同步/修正变化会连带重写 `08C0`、`08C4`、`0884` 三个块并提交；单独修改 LOD 只读写 `0884` 后提交。`0886`、`0887`、`08C6`、`08C7` 的语义尚未确认，必须保留。四种修正组合支持 bit0 控制直线、bit1 控制波纹，均为 0 开、1 关。

## 2026-10-22 开关复核

文件：`wireshark/10-22.pcapng`。抓包开始时三项功能均关闭，随后分别开启再关闭。逐帧确认：

| 操作 | 写入 | 代表帧 |
| --- | --- | ---: |
| 移动同步开 | `0884 = 02 01 01 00` | 23 |
| 移动同步关 | `0884 = 02 00 01 00` | 47 |
| 直线修正开（波纹关） | `08C0 = 02 02 05 02` | 55 |
| 直线修正关（波纹关） | `08C0 = 02 02 05 03` | 83 |
| 波纹修正开（直线关） | `08C0 = 02 02 05 01` | 107 |
| 波纹修正关（直线关） | `08C0 = 02 02 05 03` | 131 |

每个输出报告后抓到一次 Input BA 应答，包括查询报告的寄存器数据应答。传感器参数事务按这个数量读取应答；DPI 等旧事务保留各自抓包确认的读取节奏。抓包另确认修正开关通过 `08C0` 第四字节的低两位控制，其他数据保持不变。

玻璃追踪的恢复操作在第一轮休眠提示前没有捕获到 `08C4` 关闭写入；第二轮已重新恢复并记录，见下节。

提取的代表帧及原文另存为 `wireshark/gen1-features-evidence.json`。其中查询应答由四字节状态 `01 00 00 00` 加四字节寄存器值组成，例如帧 1700 的 `01 00 00 00 02 00 01 00`。写入 ACK 如 `01 00`、`02 00` 不等同于配置读回。

离线复查使用 PowerShell 7.2 或更新版本：

```powershell
.\tools\Read-RapooCapture.ps1 -CapturePath .\wireshark\gen1-features-20261021.pcap |
    Format-Table Frame, Kind, Register, Data, Hex
```

脚本只读取抓包，不连接设备；输出保留帧号、总线、设备地址和完整报文。`Response` 是控制传输返回的原始数据，解释时必须结合前面的查询，不能仅凭状态头判断寄存器类型。

最终在官方设备概况页确认：独立 X/Y 关闭；移动同步、直线修正、波纹修正、玻璃追踪均关闭；LOD 1 mm；按下/抬起均 2 ms；休眠 5 分钟；角度 0°；DIY 禁用；七档 DPI 及启用状态未变。本次继续时基线回报率已是 125 Hz，测试没有主动更改回报率。

## 当前适配判断

- 可以依据一代实测扩展：移动同步、两种修正、三档 LOD、玻璃追踪、独立按下/抬起去抖、休眠、传感器角度、独立 X/Y 表、已验证的基本按键动作。
- 还需针对操作补充证据：其余物理键地址、组合键/多媒体、宏数据与播放方式、独立 X/Y 模式位。不能把一个按键的测试扩展为整套映射均已验证。
- 尚无一代适配依据：性能模式、独立按键扫描率、低电量灯、无线策略、通信协议切换。当前官方参数页未提供相应选项；这不等于证明硬件不支持。

应用现已接入上述传感器参数和独立 X/Y DPI。物理按键、组合键、宏及缺少实测依据的功能未开放。参数写入前重新读取原始四字节块，保留未解释字段，在同一事务锁内修改、提交并读回；不使用参考文件的默认配置覆盖设备值。

新增只读实机验证了 `08C8` 的 16 字节查询和 `08C0` 四字节查询，应答仍为四字节状态加请求数据。连续控制查询之间保留约 50 ms 间隔，避免接收器返回前一条请求的内容。界面 X/Y 编辑开关不声明存在独立的设备模式位，重连后根据两张表是否不同推导编辑方式。
